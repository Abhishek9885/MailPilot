# Traditional email classification baseline

**Model version:** `email-tfidf-logreg-v1`  
**Dataset version:** `email-classification-v1`  
**Status:** Reproducible experimental baseline; not enabled in the application request path.

## Training

The training script reads [`eval/email-classification-v1.jsonl`](../eval/email-classification-v1.jsonl), validates and fits **only** rows marked `train`, and writes the versioned artifact to `apps/ai/artifacts/email-tfidf-logreg-v1/`. Validate split balance and leakage first, then train:

```powershell
uv run --directory apps/ai --project . python scripts/validate_email_classification_dataset.py
npm run train:email-classifier
```

To choose paths explicitly, run `uv run --directory apps/ai --project . python scripts/train_email_classifier.py --dataset <path> --artifact-dir <path>` from the repository root. The artifact directory contains `classifier.joblib` and `manifest.json`. The manifest records the model and dataset versions, training row IDs and data checksum, class counts, preprocessing and estimator settings, seed, runtime library versions, and artifact checksum. Validation and test message text is never passed to `fit` and does not affect the training data checksum.

Preprocessing applies Unicode NFKC normalization and whitespace normalization to the subject and body, then combines those two fields. Sender identity and other metadata are deliberately excluded to avoid learning sender-specific shortcuts. TF-IDF uses lowercase unigrams and bigrams, Unicode accent stripping, sublinear term frequency, and at most 20,000 features. Two `LogisticRegression` estimators predict the primary category and priority, each with `C=1.0`, `lbfgs`, a 2,000-iteration limit, and seed `20261119`.

Class weights are chosen from training counts: primary categories are balanced (two examples per category), so category uses no weighting; priorities are imbalanced (`low: 8`, `normal: 7`, `high: 2`, `urgent: 1`), so priority uses `class_weight="balanced"`. This weighting is a documented baseline choice, not evidence of improved quality. With one urgent training example, its learned boundary is especially unreliable.

## Inference

```python
from pathlib import Path

from mailpilot_ai.classification import EmailClassifier

classifier = EmailClassifier.load(Path("apps/ai/artifacts/email-tfidf-logreg-v1"))
prediction = classifier.predict(
    subject="Invoice 4821 is due Friday",
    body_text="Please review the invoice before the due date.",
)
```

The prediction includes `primary_category` and `priority` enum values. `predict_proba` returns class probabilities for the same two targets for evaluation. Whitespace-only subject and body raise `ValueError`; input containing no vocabulary observed during training returns `None` as an abstention. Partial vocabulary overlap is classified normally. `EmailClassifier.load` checks the manifest, artifact checksum, model version, and exact Python/numpy/scipy/scikit-learn/joblib runtime versions before loading.

`joblib` artifacts are pickle-based. Load only artifacts generated by this repository's trusted trainer; never load a model file supplied by an untrusted source. Keep the runtime pins aligned with the manifest when moving an artifact. Retraining replaces the files under that model-version directory, so retain or copy a directory to preserve a prior artifact.

## Reproducibility and limits

The random seed and estimator/vectorizer settings are explicit, and only the train split is fit. The artifact manifest captures training data identity and all runtime versions that affect serialization. Identical training runs in the pinned environment produce the same artifact checksum, covered by a test. The corpus has just 18 training messages and is synthetic, English-only, and deliberately balanced for its primary categories. The Phase 10.3 held-out results in [evaluation.md](evaluation.md) are exploratory measurements on nine test messages, not reliable estimates of real-inbox quality. The model is useful for exercising a traditional ML pipeline and serialization, not for making production decisions. Continue to use the existing analysis path until a larger independent evaluation and integration demonstrates adequate performance.

Run the focused tests and lint/type checks with `npm run test:py`, `npm run lint:py`, and `npm run typecheck:py`. Dataset split and leakage checks are available through `uv run --directory apps/ai --project . python scripts/validate_email_classification_dataset.py`.
